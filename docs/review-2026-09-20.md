Reviewed repository base: `07b7c41038e14ddc523d7fbb6f793679f6188f83`.

The live desktop app has a clear search-first layout, useful subject grouping, direct source links and a lightweight deployment model. The source registry contains 132 PMs and 76 external guideline links across 21 subjects. This review preserves that design and the extracted clinical text.

- **GL07, ESC heart failure:** the [linked publisher PDF](https://academic.oup.com/eurheartj/advance-article-pdf/doi/10.1093/eurheartj/ehag100/70807529/ehag100.pdf) confirms 2026. Kept the existing year.
- **GL21, RCEM head injury:** the [linked position statement](https://rcem.ac.uk/wp-content/uploads/2024/03/Nice_Head_Injury_Position_Statement_October_2023.pdf) concerns the 2023 NICE guidance, while its upload directory is 2024. The available text does not establish a separate publication date clearly enough to change this entry. Flag for editorial verification.

All registry IDs are unique, all 208 entries have HTTPS source URLs, and every text-enabled entry maps to the expected subject file. Text chunk page numbers are checked against the recorded page count. These checks do **not** establish that every external URL works or that each source is the latest applicable version.

## Recommended next changes, in priority order

1. **Record source provenance per document.** Add separately verified publication/revision date, validity end date where available, retrieval date, source version and last review date. The app currently has year/notes rather than a reliable expiry model. In particular, STYR-10383 is marked “Giltighet utgick 2021” in the existing registry: verify its current DocPlus replacement before relying on that entry.
2. **Check text extraction against original PDFs.** Prioritize resuscitation flowcharts, drug tables and multicolumn pages. In the live search output, the cardiac-care PM includes flattened table text and split blood-pressure thresholds. Preserve access to the original and consider a side-by-side original/text view; do not treat extracted prose as a verified substitute for the PDF.
3. **Review the core/second-line classification.** The current UI still displays “kärn” and “andra linjen” and applies different ranking/styling. Decide whether these categories have an explicit clinical/editorial definition worth presenting to colleagues. No classification was silently changed in this PR.
4. **Add Swedish search aliases for international titles.** Search currently matches the English title and society, not the linked document's full text. Editorially checked aliases such as Swedish presentation names would make external guidance easier to find.
5. **Make search results easier to scan on a phone.** A broad query currently produces long excerpt lists, including references. Consider shorter previews with an explicit expand action and downweight reference sections after testing representative clinical searches. Never silently truncate the reader itself.
6. **Add a maintenance link check.** Use a low-frequency report that separates confirmed missing documents from access restrictions/timeouts and requires editorial review before replacing links.

The changed version has therefore **not** been visually checked in that browser, on an actual phone, or in Safari/iOS. Before merging, open the branch locally and check narrow/wide screens, dark mode, reader scrolling, first-install offline use and updating from an already installed version.
- Full clinical correctness, all source links, exact extracted-table fidelity and current validity of every PM remain outside the completed verification.

## Release behavior

The new complete cache increases first-install background work to roughly 4 MB. If any required asset fails, the new service worker will not install and the previously installed version remains. Updated app versions become active after all old app tabs/windows close. The prior service worker used different caching behavior; the transition from it needs the manual lifecycle check above.
